## General

<details>
<summary>Is Dreeve the same app as "Statistics for Strava"?</summary>

Yes. Dreeve was formerly called "Statistics for Strava" and was renamed as the app grew beyond Strava into a
general dashboard for your sports and fitness data. It's the same app, by the same maintainer, 
but the repository moved to [dreeveapp/dreeve](https://github.com/dreeveapp/dreeve).

</details>

<details>
<summary>What does "Dreeve" mean?</summary>

**Dreeve** • */driːv/* • *noun*

A `dreeve` is the West-Flemish word (the birthplace of Dreeve's maintainer) for a country road lined with trees
on both sides. The kind of road every cyclist and runner loves.

</details>

## Importing & activities

<details>
<summary>Can I use both import modes at once?</summary>

No. `IMPORT_MODE` is either `files` or `stravaApi`, you can switch between them though.

</details>

<details>
<summary>Can I import a multi-sport <code>.fit</code> file (triathlon, brick workout)?</summary>

No. Dreeve imports **one activity per file**. A `.fit` file that contains multiple sport legs (a triathlon
recorded as swim → transition → bike → run, for example) is rejected, the import will fail.

Export each leg as its own file and import those separately. Most platforms let you split a multi-sport
activity into its individual activities before exporting.

</details>

<details>
<summary>Why is my activity not visible in the app after uploading it?</summary>

Almost always one of three things:

1. **The import hasn't run yet.** In `files` import mode the daemon picks up new files every 5 minutes.
2. **It was a duplicate.** Dreeve won't import the same activity twice.
3. **It failed to parse.**

</details>

<details>
<summary>Where do my files go after they're imported?</summary>

They are **deleted** from `watch/`. That happens whether the import succeeded, was skipped as a duplicate, or
failed. The raw file data is stored in the database though.

</details>

## Strava import

<details>
<summary>Do I need a Strava account?</summary>

No. Dreeve's default mode is `files`: you supply `.fit`, `.tcx` or `.gpx` files and everything is parsed
locally. No Strava account, no API application, no keys, no rate limits.

Strava import is fully supported if you want it, see [Importing activities](/importing/overview/).

</details>

<details>
<summary>Why does it take so long to import my data?</summary>

*This applies to `stravaApi` mode only. File import has no rate limits.*

Running the import for the first time can take a while, depending on how many activities you have on Strava.
Strava's API has a `rate limit` of `100 requests per 15 minutes` and a `1000 requests per day`.
We have to make sure this limit is not exceeded. See https://developers.strava.com/docs/rate-limits/.
The app makes sure there is enough time between requests to not hit the 15-minute limit.

By default, the app imports up to `250 new activities per run`.
This limit helps ensure that additional metadata can also be fetched without exceeding the daily API rate limit.

You can adjust this value in the admin panel under **Settings → Import**, with the *Number of new activities to process per import* setting.
For an initial import where you want to fetch as many activities as possible, set it to _1000_.
If you hit the daily rate limit, the app will automatically import the remaining activities the next day(s).

</details>

<details>
<summary>Can I sync multiple Strava accounts?</summary>

No, the app only supports one Strava account at a time. If you want to use multiple Strava accounts,
you will need to run multiple instances of the app, each with its own Strava client ID and secret.

</details>

## Backup & restore

<details>
<summary>What do I need to back up?</summary>

Only the **`storage/` directory**. That's it.

It holds the SQLite database (`storage/database/dreeve.db`) and the images and files the app generates
(`storage/files/`). Your original `.fit`, `.tcx` and `.gpx` files are stored **inside the database**, so there is
nothing else to keep separately.

Your `docker-compose.yml` and `.env` are configuration, not data, but keeping a copy makes a restore quicker.

</details>

<details>
<summary>How do I make a backup?</summary>

Run the backup command:

```bash
> docker compose exec app bin/console app:backup:create
```

It writes one `dreeve-<date>-<time>.tar.zst` file to the `backups/` directory, holding a snapshot of the database
and the files in `storage/` (logs excluded). It keeps the 7 most recent backups and deletes older ones.

To make a backup every night, enable the **Local backup** task in **Admin panel → Settings → Daemon**.

**Mount the backups directory.** Backups are written to `/var/www/backups` inside the container.
Add `./backups:/var/www/backups` to the `app` and `daemon` services, see [Installation](/getting-started/installation/#docker-composeyml).

</details>

<details>
<summary>How do I restore a backup?</summary>

Stop Dreeve, restore the backup in a one-off container and start it again:

```bash
> docker compose stop app daemon
> docker compose run --rm app bin/console app:backup:restore dreeve-2026-01-01-030000.tar.zst
> docker compose up -d
```

Pass the file name of a backup in the `backups/` directory. The command asks for confirmation first

The restore replaces the database and overwrites the files in `storage/` with the ones from the backup.
Logs aren't part of a backup and aren't touched.

To move Dreeve to a new server, install it there first and start it once with `docker compose up -d`. Then copy
the backup into its `backups/` directory and follow the steps above.

</details>

## Admin panel

<details>
<summary>How do I get to the admin panel?</summary>

The **Admin panel** link lives in the frontend app. Click your **profile picture** in the top-right corner to
open the dropdown menu, then choose **Admin panel**.

![Admin panel link](/assets/images/admin-panel-link.png "The Admin panel link in the profile dropdown")

</details>

<details>
<summary>I can't log in to the admin panel</summary>

The usual cause is an unescaped `$` in `ADMIN_PASSWORD_HASH`. Docker Compose treats `$` as the start of a
variable and silently mangles the hash, so you get a password that can never match. Every `$` must be doubled.
See [Admin password](/getting-started/installation/#admin-password).

</details>
